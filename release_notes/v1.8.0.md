# v1.8.0: 草稿箱可以反复改了

以前改一版就推一版，草稿箱里很快就会堆出好几篇同名文章。这一版把草稿箱从「只管写」补成「能改、能删、能续」：同一篇 Markdown 再发一次，会覆盖上次那篇草稿，而不是新建。

## 同一文件再次发布 = 覆盖更新

CLI 会在本机记录「Markdown 文件 -> 草稿 ID」的映射，位置在 `~/.config/md2wx/drafts.json`，只存草稿 ID、标题与更新时间，不碰正文。

- 首次 `md2wx article.md -p`：正常新建草稿，并记下映射。
- 再次 `md2wx article.md -p`：自动走 `draft/update`，覆盖上次那篇草稿，终端会明确提示。
- 想另发一篇：加 `--new-draft`，忽略本机记录。
- 想覆盖另一篇：`md2wx article.md -p --update-draft <草稿 ID>`。

**行为变更提醒**：同一个文件重复执行 `-p`，默认结果从「新建草稿」变成「覆盖原草稿」。如果你原本靠重复发布来留多版，请改用 `--new-draft`。

## 草稿箱管理命令

```bash
# 列出最近 10 篇草稿（标题 / 更新时间 / 草稿 ID），* 表示本机发布过
md2wx --list-drafts
md2wx --list-drafts 20

# 删除草稿，同时清掉本机对应的发布记录
md2wx --delete-draft <草稿 ID>
md2wx --delete-draft <草稿 ID> -y   # 非交互环境跳过确认
```

列表走 `draft/batchget`，删除走 `draft/delete`，与发布链路共用同一套凭据缓存、Token 失效重试与代理网关约定（`WECHAT_PROXY_URL`）。

> 走自建代理网关的用户需要网关同步放行 `draft_batchget`、`draft_update`、`draft_delete` 三个动作；wx-serv 侧的代理路由已补齐，重新部署网关后生效。

## 降级与边界

- 本机记录的草稿已在公众号后台被删除时，`draft/update` 返回 40007，CLI 会自动清掉失效映射并改为新建草稿，不会卡在半路。
- 显式 `--update-draft` 指定的草稿不存在时直接报错，不会偷偷新建，避免发错位置。
- `--dry-run` 现在会区分 `draft/add` 与 `draft/update`，并打印对应的 media_id，仍然不获取凭据、不发任何请求。
- 从 stdin 读入、不带文件路径时，映射退化为按标题记录，避免误覆盖无关文章。

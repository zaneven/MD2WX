# v1.6.1: 草稿箱常驻侧栏与引用分行修复

本次更新两件事：草稿箱从头部浮层搬进编辑器左侧常驻，引用块恢复逐行换行。

## Web Studio：草稿箱改为常驻侧栏

- 「草稿箱」从头部下拉浮层移到 Markdown 编辑器的左侧，成为常驻栏：顶部是列表与「新建」，底部显示草稿篇数与「本地自动保存」。
- 编辑区与预览区相应收窄；窗口宽度低于 1180px 时侧栏自动压缩到 188px，保证仿真实机预览不被挤坏。
- 列表在编辑过程中自动刷新（标题、相对时间、活动草稿高亮），内部做了 500ms 节流与指纹比对，只在标题、时间或活动态真的变化时才重建 DOM，输入时不会反复重绘。
- 草稿的载入、新建、删除、自动保存行为与 v1.6.0 一致，`localStorage` 数据格式未变，升级不会丢稿。

## 渲染：引用块恢复逐行换行（行为变更）

v1.5.0 引入 CommonMark 软换行语义后，文章开头常见的作者、标签、摘要等连续引用行，会因中文相邻字符被直接拼接成一段，推送微信后塌成一整行。现在：

- 引用块内层按作者手写的分行渲染，行与行之间插入 `<br/>`，`>` 空行生成的间隔、嵌套引用、引用内列表照旧。
- 引用块之外的普通段落仍保持软换行语义：源码为排版而折的行不会变成换行，中文段落的拼接行为不变。
- 行尾已有两个空格或反斜杠的硬换行标记不会重复插入换行符。
- CLI 与 Web 端仍是同一套语义，双端 golden 一致性测试继续通过。

如果你原本依赖「引用块内多行自动拼接成一段」的写法，请把该段写成单独一行。

## 校验

- Python 单测 143 项通过（新增 3 项：引用块分行、硬换行标记不重复、引用块外软换行仍生效）。
- Web 端 48 项通过（新增 2 项同源用例），`npm run build` 无错误，双端渲染一致性比对通过。
